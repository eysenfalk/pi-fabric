# Plan one bounded change

- Read the applicable repository instructions and trace the smallest relevant execution path.
- Extract the observable outcome, explicit constraints, non-goals, authority, and decisive evidence. Record decision-relevant repository facts with concrete file, symbol, command, or documentation sources.
- Ask the human only when an unresolved answer materially changes the outcome, architecture, authority, or acceptance. Return all currently foreseeable related questions together rather than revealing them serially.
- On an incremental replan, retain the supplied facts and settled decisions; reconsider only what the new answer or requested revision changes.
- Resolve ordinary reversible engineering choices from repository evidence and expose the chosen defaults as assumptions or risks.
- Select specialist Skills semantically from the supplied active catalog; never infer them from keyword rules.
- Propose implementation, proportional verification, optional risk-justified review, and honest closure.
- Do not add stages or abstractions for merely conceivable low-impact cases.
- Do not edit files in this stage.
